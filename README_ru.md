### Возможности

- Отображает всплывающее уведомление (тост), когда приложение получает повышенные привилегии.
- Поддерживает настройку текста уведомления.
- Поддерживает игнорирование уведомлений о предоставлении прав для указанных приложений.

### Установка

Скачайте пакет модуля со страницы релизов (Releases), затем выберите и установите его в KernelSU или BakaSU.

После установки перезагрузите устройство, чтобы модуль вступил в силу.

Этот модуль не зависит от Zygisk или MetaModule.

### Совместимость

- Официальный KernelSU, сборка 32457 или новее, с доступным SuLog.
- BakaSU (ранее ReSukiSU), актуальные сборки 4.x.
- Другие форки KernelSU, сохранившие тот же ABI событий SuLog и ioctl `KSU_IOCTL_GET_SULOG_FD`.

Установщик проверяет наличие функции SuLog в ядре, а не полагается на
`KSU_KERNEL_VER_CODE`, поэтому форк не отклоняется только из-за другой схемы
нумерации версий.

BakaSU управляет SuLog как функцией. Модуль объявляет `managedFeatures=sulog`,
перехватывает читатель `sulogd` и сохраняет объявление, чтобы второй читатель
не запустился повторно. Пока модуль установлен, переключатель SuLog в менеджере
управляется модулем и не может быть изменён вручную.

### Как это работает

Когда логирование Su включено, реализация root запускает постоянный читатель,
который получает данные логов, пересылаемые ядром, и записывает их в файл.
В KernelSU этот читатель работает внутри ksud, а в BakaSU — как отдельный
демон `sulogd`.

Эти данные поступают в реальном времени, что делает их идеальными для мониторинга событий.

После установки модуля и завершения загрузки устройства модуль завершает работу
оригинального процесса, отвечающего за запись логов (того, который владеет
очередью). Затем он получает файловый дескриптор, используемый для приема
соответствующих данных (этот дескриптор может удерживать только один процесс,
поэтому оригинальный процесс должен быть остановлен), и берет обработку событий
на себя.

Пока модуль владеет очередью, он сам продолжает писать файлы SuLog в исходном
формате (`sulog-YYYY-MM-DD[-N].log` в `/data/adb/ksu/log`, ротация на 10 МиБ,
хранение 3 дня). Поэтому страница SuLog в менеджере снова работает и может
использоваться для аудита запросов su, включая неудачные.

Если обнаруживается, что Android-приложению предоставлен root-доступ, модуль
получает информацию о приложении и отображает уведомление при выполнении
настроенных условий.

### Важные примечания

Модуль сам пишет SuLog, поэтому страница SuLog в менеджере остаётся доступной.
Файлы лежат в штатном месте и формате, поэтому другие инструменты разбора
логов продолжают работать.

Параметр «Автоудаление логов» удаляет существующие файлы SuLog при запуске
модуля (по умолчанию выключен). Если он выключен, модуль дописывает сегодняшний
файл и хранит историю 3 дня.

Удаление модуля автоматически восстанавливает штатный читатель SuLog.
